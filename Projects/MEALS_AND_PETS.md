# 放纵餐统计与精灵养成

最后更新：2026-10-02

状态：核心规则已在主应用开发版实现并验证。下文继续区分用户确认与前期提案；当前默认值见本文末与 `IMPLEMENTATION.md`。

## 用户已确认

- 在本 PWA 内增加放纵餐统计模块，并维护分数。
- 每周不超过 1 次算达标，0 次也达标；超过 1 次算超标。
- 首个坚持周加 1 分，连续坚持按 1、2、4……翻倍加分。
- 首个超出周扣 2 分，连续扣分同理翻倍。
- 达标与超标切换时，原连续倍数重置，新连续从 +1 或 -2 开始。
- 总分初始 60 分；第一只精灵初始 60 分，后续新精灵初始 0 分。总分和各精灵分分别维护，均不设上限、最低为 0。
- 提供可视化精灵养成，分数越高，精灵越高级、越大、越好看。
- 一个精灵满级后可解锁其他精灵。
- 扣分后，精灵随自身当前分数降级、变小；重新加分后可恢复。
- 已解锁精灵永久保留，可以切换展示，不因分数降低重新锁定。
- 每只精灵独立培养；每周总分照常加减，精灵中只有当前装配的一只参与加减分，其他精灵分数不变。
- 可以随时切换装配，结算时装配的精灵承接该周全部加减分。
- 总分用于历史统计，不参与精灵成长；精灵形态由自身分数决定。总分独立累计，不以各精灵分数之和替代，切换或解锁精灵不重置总分。
- 后续精灵的满级门槛逐步提高，具体数值待模拟；先提供多种视觉风格让用户选择。
- 精灵采用动态 3D，角色系列覆盖十二生肖、常见海洋生物和鸟类（含鹰类）；图鉴与探索原型见 [PET_CATALOG.md](PET_CATALOG.md)。

## 周结算与历史修正（已确认）

- 固定北京时间（Asia/Shanghai），每周一 00:00 至下一周一 00:00 之前为一周。
- 下周首次打开时，确认上周放纵餐次数后结算；无记录周保持待确认，不能自动按零次奖励。
- 首次使用从下一个完整周开始计分，当前不足完整一周的数据可以记录，但不计周分。
- 允许补记、编辑和删除；历史餐记录改变后，重算该周及受影响的后续分数，仍归属原来结算的精灵。
- 历史重算后已解锁精灵继续保留。
- 多个待确认周的顺序、用户暂不确认时的提示及周结算操作细节在实现设计中确定。

## 已确认计分规则

按周判断达标或超标，使用对应连续周数计算加减分。达标与超标切换时连续周数从 1 重新开始；同一周不按每多一餐重复扣周分。周界限与确认方式按上节执行。

| 连续同类结果周数 n | 达标周加分 | 超出周扣分 |
| --- | --- | --- |
| 1 | +1 | -2 |
| 2 | +2 | -4 |
| 3 | +4 | -8 |
| 4 | +8 | -16 |

规则变化值：达标为 `2^(n-1)`，超标为 `-2^n`。每周使用同一规则变化值分别更新两类分数：

- 总分：`max(0, 结算前总分 + 规则变化值)`。
- 结算时装配精灵：`max(0, 该精灵结算前分数 + 规则变化值)`。
- 其他精灵：分数不变。

扣分触及 0 时，两类分数各自截断，因此实际变化值可能不同；精灵未扣完的分数不转给其他精灵，也不额外加扣总分。不存在未经用户指定的倍增上限或分数上限。

示例（全程装配首只精灵）：达标、达标、超标、超标、达标，变化依次为 `+1、+2、-2、-4、+1`，该精灵分数依次为 `61、63、61、57、58`。

独立截断示例：结算前总分 70，装配精灵 5，另一只精灵 65；该周规则变化为 -8，则总分变成 62、装配精灵变成 0、另一只仍为 65。之后若规则变化为 +1，两者分别变成 63 和 1。

0 分边界的实现解释：只截断余额，不积累负债；连续超标仍延续超标周数，直到出现达标周才重置。按当前规则推导，之后第一个达标周从 0 加至 1，不需偿还被截断的扣分。

## 独立培养设计草案（尚未确认）

- 总分、各精灵分数、当前装配 ID 及永久解锁集合均需保存；这部分已确认，以下为实现细则建议。
- 按现有连续规则解释，连续周数由放纵餐周结果决定，切换精灵不重置连续倍数。
- 建议解锁不消耗已有精灵分数；首只 60 分、新精灵 0 分已确认。
- 满级建议只限制外观／等级，成长分仍可累计，不转移超额加分，符合无上限分数与仅装配精灵参与计分；具体满级阈值待设计。
- 每周结算时保存装配精灵 ID；结算后再切换不挪动历史加减分。补记重算使用原周接收对象已确认。
- 视觉暂按幼体与进化形态成对探索，比较风格；不代表最终只有两个成长阶段。
- 五个外观阶段、首次满级免费解锁下一只、同一只重复满级不重复解锁仍为设计提案；后续满级门槛逐步提高已确认。

## 后续规则与设计事项

- 一周未结束时，建议展示本周次数和预估变化；具体确认结算界面待设计。
- 养成阶段、满级阈值、精灵数量、外观风格及 0 分／60 分对应形态尚未确定。
- 精灵满级解锁新精灵后再降级，不因普通扣分撤销已解锁精灵；重复满级是否产生新的解锁资格需定义，避免重复领取。
- 独立成长、永久解锁与结算时装配对象接收整周分数已确认；解锁是否消耗分数与满级后的展示仍待定。
- 等级与视觉尺寸的成长映射需适配小屏幕；无上限分数不等于无限放大屏幕中的精灵。
- 当前计分只关联放纵餐规则；没有用户确认前，不把运动次数或成绩加入分数。

## 建议展示内容（尚未确认）

- 本周放纵餐次数、当周目标、添加记录入口。
- 当前装配精灵分数、连续达标／超出周数、本周预估变化。
- 独立总分及其历史变化，用于查看长期坚持情况，不驱动精灵形态。
- 周历史与加减分原因。
- 当前精灵阶段、下一阶段进度及可随时装配的已解锁精灵列表。

## 数据与验证

- 完整备份应覆盖原始餐记录、规则版本、周结算流水与精灵进度，扩展草案见 [DATA_FORMAT.md](DATA_FORMAT.md)。
- 分数从原始记录与规则可追溯；重启、重复进入或恢复备份不能造成重复结算。
- 指数倍增采用精确整数表示与计算，不用浮点数静默舍入，不擅自封顶。
- 核心计分边界确定后，通过连续加分、连续扣分、正负切换、缺失周、历史重算及恢复备份场景验证。
- 总分与装配精灵分分别验证 0 分截断；切换后不改写未装配精灵，不重置总分，恢复后两类分数与历史计分归属一致。

## 当前开发版默认值与验证

- 用户已授权设计后开发。当前 24 种精灵，首次可任选；五阶段阈值为满级的 0／20%／45%／70%／100%，满级按解锁序号 120×2^n；成长配置版本 growth-draft-v1。
- 首次满级获得一次免费领养资格，可任选未解锁精灵，不扣分、不重复领取；新伙伴 0 分，需手动装配。该细则属于本轮实现选择，可后续调整。
- 多个待确认周按从早到晚逐周确认；确认前显示次数和当前接收伙伴，无记录不自动结算。修改历史餐记录即重算，保留原归属、永久解锁与已用领取资格。
- 测试覆盖 90 周精确整数增长、连续切换、独立最低 0、历史重算、永久解锁、重复结算阻止、导出恢复；实际浏览器覆盖六周达标后解锁／换装、超标扣分与历史修正。
